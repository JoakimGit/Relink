I'm building a link shortening app, that besides the link shortening also provides management for your links, with things like groups (like folders) and tags.
When creating links, there are also various options like start date, expiration date, password lock, max usages, etc. You can check the EF Core entity for the properties that currently exist. 
The home page should showcase a row with the brand name "ReLink", a search input for searching through your links, and a button for creating a new link.
Below that should be a list/grid view of your links as cards. They would showcase at a minimum the shortened url, the original url, click count, tags, and icons for various settings active on the link, like a lock if it's password gated, etc. When clicking the create button, it would open a modal with input fields for all the different options. The cards should have an action menu that can be opened (through an ellipsis icon or the like) with actions for deleting, editing or copying the shortened url. I'm not quite sure how tags should work. If those are created separately and persisted as their own entities (that's how the db context is looking like atm), after which the user can then select tags from a dropdown, or if it's just a free text field, or a free text field, where they are also created as entities at the same time. Also not sure how groups will work yet, but I think this can be implemented later once the base functionality is in place and I can get a better sense of the app. 
I've built out most of the backend already, but the frontend is mostly missing. I have created the angular project inside the Relink.Client folder and scaffolded a few things, like the home page, which currently fetches links and displays them with partically hardcoded data. The current UI for that can be scrapped. The project uses tailwind for styling, ng-icons for icons and spartan-ui for shared generic ui components (it's the angular fork of shadcn). Aspire orchestrates the local development setup. The api is structured with 1 file per endpoint, which contains everything for that endpoint, unless there is shared code to be used in other endpoints.
